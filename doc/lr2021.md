# LR2021 transceiver

OpenAce supports `Sx1262` and `Lr2021` through `AbstractTransceiver`. Both use the
same radio tuner, protocol encoders/decoders, TX queue, GPS transmission gate,
Manchester processing and `RxDataFrameQueue`. A radio slot retains its `_Radio_N`
identity regardless of the selected chip. Mixed SX1262/LR2021 configurations are
supported. Runtime radio numbers are assigned consecutively to successful loads,
independently of configuration suffixes; failed loads consume no number.

The implementation targets the existing sub-GHz GFSK and LoRa profiles. It does
not add FLRC, BLE, LR-FHSS, 2.4 GHz, or new aviation protocols. It has not yet been
validated over the air on LR2021 hardware.

## Source layout

`src/lib/tranceiver` replaces `src/lib/sx1262`. Existing Semtech SX126x sources are
in `sx1262driver`; the official LR20xx sources are in `lr2021driver`. The latter
contains an `UPSTREAM.md` recording the exact source commit. Both chip HALs live
outside the imported sources.

LR2021 initialization loads Semtech's LR2021 PRAM patch, including the sub-GHz
DCDC sensitivity and LoRa reception fixes. LoRa configuration applies the legacy
SX1276 compatibility workaround for interoperability. Sleep is not used by the
shared task; any future non-retained sleep must reload PRAM after wakeup.

## Configuration

The firmware currently embeds `src/pico/gatas_default_config.json`, with optional
`gatas_local_config.json` overlay. The INI file contains matching settings for
reference, but is not currently the firmware build input.

1. Configure the actual board pin map under the selected hardware profile with
   a `Lr2021_0` or `Lr2021_1` entry.
2. Enable the required `Sx1262_N` and/or `Lr2021_N` modules. Matching suffixes
   may coexist when they describe separate hardware. At most `GATAS_MAX_RADIOS`
   radios can load; SX1262 is tried before LR2021 at each configuration index.
3. Set the oscillator and RF-switch settings for the exact module schematic.
4. Restart. Confirm initialization succeeds before setting `txEnabled` to true.

Pin-map fields:

| Field | Meaning |
| --- | --- |
| `CS` | MCU GPIO connected to LR2021 NSS |
| `BUSY` | MCU GPIO connected to LR2021 BUSY |
| `DIO1` | MCU GPIO connected to the selected radio IRQ output; the historical key name is retained even when the radio output is DIO7 |
| `DEV` | AceSpi instance, 0 or 1; defaults to 0 |
| `RST` | Optional **dedicated** MCU reset GPIO. Omit when reset is owned by AceSpi. |

The selected `AceSpi_N` config supplies SCK, MOSI and MISO. Shared reset stays
owned by AceSpi and must not also be configured as a dedicated radio RST.
Recovery uses standby and reconfiguration, never a shared reset pulse.

Per-device settings stay in the top-level `Lr2021_N` entry:

| Setting | Default | Meaning |
| --- | --- | --- |
| `txEnabled` | false in shipped config | Permit transmission when GPS fix is valid |
| `offset` | 0 | Frequency correction in Hz; positive or negative |

Board settings belong beside the pins in the selected hardware profile's
`Lr2021_N` entry, for example `PICO_2RADIO/Lr2021_0`. These settings do not fall
back to top-level radio values:

| Setting | Default | Meaning |
| --- | --- | --- |
| `capabilities` | empty | Comma-separated RF capabilities supported by this board's radio and antenna path |
| `irqDio` | 7 | LR2021 DIO number routed to MCU `DIO1`, valid 5–11 |
| `tcxoVoltage` | -1 | Crystal mode; 0–7 select 1.6, 1.7, 1.8, 2.2, 2.4, 2.7, 3.0 or 3.3 V TCXO supply |
| `tcxoStartupUs` | 5000 | TCXO settling time in microseconds, 0–100000 |
| `rxSwitchDio` | -1 | No external RF switch; otherwise radio DIO 5–11 driven high during LF RX |
| `txSwitchDio` | -1 | No external RF switch; otherwise radio DIO 5–11 driven high during LF TX |

`PICO_2RADIO/Lr2021_0` describes the Waveshare Core2021-HF with a 32 MHz crystal,
so `tcxoVoltage` is `-1`. The Wio-LR2021 entries in the other hardware profiles
use `6` for the 3.0 V TCXO supply. The voltage field is an enum code, not volts;
`0` selects 1.6 V and does not disable TCXO mode.

If RX/TX switch settings select the same DIO, it is high during either operation.
Switch DIOs must differ from the IRQ DIO. These options cover active-high switch
controls; boards requiring other switch truth tables need an explicit adapter
extension. The PA uses Semtech's LF full single-ended default configuration.
Validate the module matching network, supply, oscillator and antenna path before
bench transmission. Missing pin maps fail initialization rather than guessing.

`txEnabled` and `offset` are exposed in SystemGUI. Board settings and pin maps are
configured in JSON and require a restart. Runtime configuration is read
synchronously and no module retains a `Configuration` reference.

When updating an existing saved JSON configuration, move capabilities and the
five LR2021 board settings into their hardware-profile entries. Keep `txEnabled`
and calibration `offset` top-level. Firmware updates do not replace saved JSON,
and the driver no longer reads the old top-level board settings. Restart after
applying the updated profile.

## Compatibility and validation

- Software Manchester coding and decoding remain shared with SX1262.
- GFSK uses the SX126x-compatible eight-bit variable-length header where needed,
  CRC/whitening disabled, and the same RX sync-word skipping convention.
- LR2021 RX bandwidth is rounded up using Semtech's bandwidth-selection helper;
  it is not assumed to have the same bandwidth enums as SX1262.
- LoRa uses SF7, existing bandwidths and per-packet coding rates, restoring the
  RX default after TX. Variable-length LoRa RX accepts up to 255 bytes.
- LR2021 uses RX single mode and explicit rearming so FIFO contents remain stable
  while the shared task reads a packet. The PRAM patch is loaded first.
- HAL errors are bounded and propagated; CS is released after short transfers.
- Driver IRQs are translated to common events while retaining the raw mask for
  acknowledgement retries. TX completion is counted only on TX_DONE.

Desktop checks are in `src/lib/tranceiver/tranceiver_tests`, included in the
normal desktop build. They exercise actual firmware sources with GPIO/SPI mocks.

Before declaring RF equivalence, test each configured OpenAce profile in both
SX1262-to-LR2021 and LR2021-to-SX1262 directions. Include Manchester payloads,
variable frame lengths, LoRa coding-rate changes, frequency hopping, RX/TX
turnaround, shared-SPI contention, dropped IRQs and sustained traffic. Measure
power, frequency error and packet loss with the actual board. No firmware has
been flashed as part of this change.
